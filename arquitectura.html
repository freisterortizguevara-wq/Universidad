1. El Diagrama General (Cómo fluye todo)

Imagina tu proyecto como una cocina de restaurante. Tienes al cliente (Frontend), al mesero (Backend API), al chef (LangGraph) y a la despensa (Neon).

[ USUARIO ] │ (Escribe una pregunta en el navegador) ▼ [ FRONTEND: Streamlit ] ──(Petición HTTP POST)──▶ [ BACKEND API: FastAPI (Puerto 8001) ] ▲ │ │ ▼ │ [ CEREBRO: LangGraph ] │ │ │ (¿Necesito buscar datos?) │ │ │ ▼ │ [ HERRAMIENTA: Búsqueda ] │ │ │ ▼ │ [ BASE VECTORIAL: Neon ] │ │ │ (Devuelve respuesta JSON) │ (Devuelve los PDFs) └──────────────────────────────────────────────────────┘

2. El Backend (La Cocina)

FastAPI El Mesero

El archivo 6_agente_orquestado.py tiene una API creada con FastAPI. ¿Qué hace? Se queda escuchando en el puerto 8001 esperando a que el frontend le envíe una pregunta. Cuando llega, la convierte a un formato que LangGraph entienda.

LangGraph El Chef (El Cerebro)

No usamos un simple "chat" donde la IA responde cualquier cosa. Usamos un Grafo (un diagrama de flujo).

  • Nodo Agente: Recibe la pregunta. El LLM decide: "¿Respondo directo o uso mi herramienta?".
  • Arista Condicional: Si es un saludo, responde directo. Si pregunta por la universidad, se desvía al nodo de herramientas.
  • Nodo Herramienta: Va a buscar a la base de datos.

Neon + pgvector La Despensa

Es una base de datos en la nube (PostgreSQL). Tiene un superpoder llamado pgvector. En lugar de buscar palabras exactas (como un "Ctrl+F"), busca por significado matemático. Si preguntas "¿Cómo me inscribo?", encuentra el documento que habla de "matrícula", aunque no usen la misma palabra.

💡 Frase para la entrevista:
"Para la orquestación, implementé un patrón de Corrective RAG con LangGraph. Si el agente decide que necesita contexto, utiliza una herramienta que consulta a Neon mediante similitud de cosenos. Si el documento encontrado no es relevante, el flujo no alucina, sino que se deriva a soporte humano."

3. El Frontend (La Cara Bonita)

Streamlit La Interfaz

El archivo app.py es una aplicación web. No usamos React ni HTML puro (aunque inyectamos CSS). Usamos Streamlit porque permite crear interfaces en Python puro.

  • Peticiones HTTP: La interfaz no procesa IA, solo hace peticiones con requests.post al backend y pinta lo que recibe.
  • Estado de Sesión: Usamos st.session_state para generar un ID único (UUID) por cada visitante. Esto permite que el agente recuerde de qué estaban hablando.
  • Ingesta de Datos: En la pestaña de Admin, el usuario sube un PDF. Streamlit lo envía a otra API (Puerto 8000), que lo corta en pedazos, lo convierte en vectores y lo guarda en Neon.

4. ¿Cómo explicarías la arquitectura si te preguntan?

Usa esta estructura lógica:

  1. El flujo: "El usuario interactúa con una interfaz hecha en Streamlit. Esta interfaz está desacoplada de la lógica de negocio; solo se comunica vía API REST con FastAPI".
  2. La ingesta: "Cuando subimos un PDF, un endpoint usa PyPDFLoader para extraer el texto, lo divide con un TextSplitter (haciendo chunking) y lo vectoriza usando HuggingFace, guardándolo en Neon".
  3. El agente: "Cuando el usuario pregunta, el grafo de LangGraph usa el modelo Llama 3 (en Groq) para decidir si usar la herramienta de búsqueda vectorial. Si la usa, el LLM lee el contexto recuperado y genera una respuesta basada SOLO en los documentos".
  4. La memoria: "Para que el chatbot no sea amnésico, inyecté un Checkpointer de SQLite que guarda el historial por cada `session_id`".
💡 Pregunta trampa de entrevista: "¿Qué pasa si Groq o Claude se caen (fallan)?"
Tu respuesta: "La interfaz está preparada con bloques `try/except`. Si la API falla, el frontend atrapa el error `ConnectionError` o `Timeout` y le muestra un mensaje amigable al usuario invitándolo a usar el formulario de soporte humano. No se rompe la página".

5. Mejoras que puedes mencionar (Para sonar Senior)

Si te preguntan "¿Qué le falta al proyecto?" o "¿Cómo lo llevarías a producción?", di esto:

  • Seguridad: "Actualmente el frontend usa `session_id` en memoria. En producción, implementaría autenticación con JWT y guardaría los hilos de conversación vinculados al ID del estudiante en una base de datos relacional".
  • Costes de IA: "Para optimizar costes, implementaría un enrutador semántico. Las preguntas simples las respondería un modelo pequeño (como Llama 8B) y las consultas complejas las derivaría a Claude, que es más potente pero más caro".
  • Evaluación: "Actualmente validamos a ojo. En producción, usaría RAGAS o LangSmith para medir la fidelidad (Faithfulness) del RAG automáticamente y evitar regresiones en los prompts".
